# 2.6.0 二十四节气时令视觉

从 2.5.0 起的 26 个 commit 是一条完整主线：让池塘**跟着当天节气走**，而不是四季背景贴图轮换。本次是这个系统的第一个完整版本。

## 背景

`getSolarTerm(date)` 早已用黄经每 15° 算出精确到分钟的节气，`env.solarTerm` 也早已传进渲染 options —— 但它当时**只出现在 HUD 文字里**（`· 立春`），对画面零影响。用户看到的是「每个节气之间都一样」。

规划稿见 [SOLAR-TERM-PLAN.md](SOLAR-TERM-PLAN.md)。

## 实际改动

### 一、节气档案与渐变骨架

- 新增 `src/engine/almanac.js`：24 档 `TERM_PROFILE`（温度、荷叶、荷花、花苞、莲蓬、落叶、霜、结冰、雨势等物候量）+ `SOLAR_TERMS` **历法序** + `TERM_SEASON`。
- 新增 `src/engine/term-visual.js`：把档案翻译成渲染层参数（各类计数、连续开放度、形态标签）。
- 相邻节气不再是硬切换，而是**秩次等距 + 结构化染色**的连续渐变（`almanac.js` 记录了第 1~15 次量具失效过程）。同季中位色差 ΔE 1.19 → **4.84**。

### 二、节气水色改用 HSV 变换

RGB 逐通道乘色**已证伪**—— 逐通道缩放恒等保饱和度，实测洋红偏 39.5%，参考图的水区饱和度比底图低 46~54%。正解是 24 组 HSV 位移（`TERM_TINT_HSV`：dh/ks/kv）+ shader 内 `rgb2hsv`/`hsv2rgb`，角度插值走环形短路径。同季中位 ΔE 0.06 → **5.12**。

### 三、昼夜连续化

`night` 布尔改成连续标量 `dayLight`（0..1）。**幅度类**走 `byDaylight()` 插值，**门控类**（如萤火虫、蝴蝶）保留布尔 —— 否则正午会出现萤火虫。四段权重与 `getDayPhase` 的 5/7/17/19 对齐。

### 四、冬季画面连续削减三次

从「冰封」一路减到只剩**浮霜 + 降雪**：① 去掉整池冰层 ② 去掉岸边积雪与雪粒 ③ 去掉冰下泉眼与蒸汽。**档案里的 `ice/frost/snow` 维度一律不动** —— `ice` 仍是降雪强度的唯一来源，删了就少了连续档位。

### 五、荷花形态重做 + 物候重排

- 形态：三层花瓣（7/6/5 瓣、长卵形顶端圆钝）、逐层张角、俯视压扁 `FLORA_FLAT=0.62`、按簇心聚拢。
- 开花过程：`rawOpenness` 由档案 `lotus` 派生，**每朵按自己的相位缓开**（周期 34 秒），不是整档同步。
- **物候重排**（据江南荷花真实物候时间轴）：**峰值在大暑**（8 朵 + 22 片叶，全 24 档最多）；春组零花零苞（钱叶期）；立秋起花退坡、莲蓬接力（1 → 3 → 5）；小雪起水面无叶。
- 花苞三形态：尖苞（立夏，瘦长笔直）/ 将开（小满–大暑，饱满微张露瓣）/ 残花枯瓣（立秋–寒露，褐变外翻下垂）。
- ⚠️ **参考图也会误判**：原档案照抄参考图「春分七八支花苞待放」，而江南春分是钱叶期、谷雨才孕蕾 —— 原档案花期提前约 20 天。参考图与真实物候冲突时**以物候为准**。
- **立叶与浮叶分离**（`standLeaf` 通道）：荷塘的叶分两类 —— **浮叶**贴水（钱叶期就有十几片）、**立叶**叶柄挺出水面把叶盘举高（谷雨才冒尖）。两者物候曲线不同步，而档案原先只有一个 `leaf` 通道，于是「立夏立叶 4–5 片」与「谷雨已有十几片浮叶」**不可能同时成立**，上一版只能回避其中一句。现在两通道各管一种叶，立叶画成**水面叶影 + 立柄 + 举高的叶盘**三件套（叶影是 1× 下最主要的辨识特征）。

### 六、底图与跨季过渡

- 新增 `src/engine/term-images.js`：底图改按**节气口径**选图，跨季边界恰好 4 处（谷雨→立夏 · **大暑→立秋** · 霜降→立冬 · 大寒→立春）。
- 相邻节气 **8 秒交叉淡入**（单 pass 双纹理 `uImage`/`uImageB`/`uFade`）。
- 缺失纹理改为 `throw` + `onerror`。原来会静默用槽位名当文件名 ⇒ 404 ⇒ `onload` 永不触发 ⇒ **画面停在旧图且无报错**。

### 七、雨水真的会下

「该下雨」原先由**天气**决定，于是演示轮转到雨水却晴天。新增档案 `rain` 维 + 独立的 `termDrops` 通道：**天气决定「要不要更猛」，节气决定「有没有」**（与降雪同构）。同时补环境压暗与三处同帧门控（否则亮雨丝压在晴天水色上读成「白色竖线」，或雨天出现蜻蜓）。

### 八、评审清单四条整改

| 条目 | 结果 |
|---|---|
| 冬季水面残留橙黄枫叶 | 已改枯叶色 + 深冬清零（**换颜色而非减数量** —— 违和真源是暖色高饱和压在冷背景上） |
| 「两处串味」 | 指控本身经**像素级实证推翻**（立夏右上角是夏季底图自己的睡莲，非春桃），但顺藤查到真缺陷：`blendTerm()` 返回对象**压根没有 `bud`/`pod` 键** ⇒ 过渡中途花苞凭空消失、到新档时带着上一档的花苞 |
| 「大暑荷量低谷」 | 判据方向本身就写反了（写着「峰值在夏至」），已按物候翻转 |
| 「雨水不下雨」 | 见第七条 |

### 九、焦散光网（补记：落在 2.5.0 与 2.6.0 之间的未记录工作）

commit `fd4a7de`。`landscape.js` 的片元着色器过去只有叶片摇曳，水面是死图。
本次盘点发现它**已实现且有量具**，但从未写进任何发布说明，而「已知未做」里
还挂着一条与之相反的旧记录 ⇒ 两边都错，且是相反方向的错。

- `light-field.js` 新增 CAUSTIC 冻结常量块（ink/scale/warp/gate/shallowGain
  + weather 与 season 门控）。需求 §10.5 未提焦散，故每个数都注明是按参考图
  目测标定；唯一硬约束是 ink 上界 0.16（再高会洗白浅水区）。
- `landscape.js` 新增 `causticNet()`：域扭曲 + `fract()` 周期网格 + Chebyshev
  距离脊线，7 个新uniform。合成时**只加光不减光**，并乘既有水掩膜
  `min(g,b)-r`，因此只在水域生效。low 质量整档关闭（高频网会混叠成灰雾）。
- 三个踩过的坑：① GLSL 在 JS 模板字符串内，**禁 `//` 行注释、更禁反引号**，
  必须用 `/* */` ② `uv*scale` 只改格子大小不改密度（实测 scale 3→20 占空比恒 19%），
  改用 `fract((q+drift)*cells)` 后 `cells` 才是真控制
  ③ **探针判据自身失效过两次**（判「参数生效」一开始用覆盖率，
  而覆盖率本来就该大致恒定 ⇒ 改用亮线游程；游程法在 cells 过小时量具失效）。
- 量具 `npm run check:caustic` 5 条：占空比 3.2% · 随时间流动 ·
  内部形变非平移 · 峰均比 49.8× · cells 是真控制。

## 验收工具

新增 15 把量具与 6 个护栏文件。要点：

- **`check:lotus:pheno`（18/18，纯 Node <1s）** —— 验**形状**而非落点：峰值唯一性、三伏递增、秋组退坡、莲蓬接力、春组空水面、立叶晚于浮叶出现且明显少于浮叶。判据表从物候时间轴**抄**，不从档案反推（反推 = 用实现验证实现，恒绿）。
- **`check:lotus`（29/29，像素级）** —— 渲染层自报 `floraManifest`（落点比例坐标 + 像素半径 + 形态），只在落点处做两图差分，与颜色彻底解耦。五类形态（浮叶/立叶/花苞/荷花/莲蓬）逐档逐落点验收。
- **`check:rain`（13/13）** —— on/kill 差分 footprint。反证手法是**把 `syncRain` 换成 no-op**（改档案会连翻译层一起变，分不清「没画」与「算错」）。
- **`check:term:delta`（10/10）** —— 含**GPU 前置门**：只看 `landscape.ready` / `!!uniforms` / `bgCanvas.style.opacity`。起因是 GLSL ES 1.00 **没有 `%` 运算符**，`int(floor(h))%6` 让整个 shader 编译失败，而构造器 `try{init()}catch{opacity=0}` **静默吞掉** ⇒ 退化成 CSS 兜底图，页面正常、参数也对、画面逐位不变。
- **`check:terms:desktop`（10/10，真实 Electron）** —— `dist` 里**没有引擎句柄**（`Pond.jsx` 被 `import.meta.env.DEV` tree-shake，刻意设计），无法冻结 ⇒ 改用**静止像素掩膜**：每档连截两张自比得动像素，档间差只在两档都静止的交集上统计。
- **`_pheno-falsify.py`** —— 双向验证脚本，四条反证全部产出明确不同读数（改回旧值后分别报 4/1/1/5 项红）。

> 判据设计上踩过的坑已沉淀为方法论：绝对特征量在多通道画面上必然失效、「加了量但指标一位没动」= 指标压根没在量目标量、阈值要从反证反推、判据不能锚死某个档案值。

### 层② 的两条补图路线为什么都不通（2026-10-08 实测）

缺口定位： 从 manifest 反查出 24 档分4 槽位，
唯**只有 4 处跨季边界**是缺口（谷雨→立夏、大暑→立秋、霜降→立冬、大寒→立春），
其余 16 档在槽位内部，由  的 HSV 管线承担。

| 路线 | 做法 | 实测 | 为什么不通 |
|---|---|---|---|
| A · AI 生图 | 双图输入：winter 定构图 + autumn 定色 | 与 autumn **8.46**（合格）· 与 winter **30.81**（超上限近一倍） | 图生图是**编辑**不是**合成** —— 做不到「几何取A、色取B」，整张停在秋那侧。且模型把荷塘画成礁石浅滩，构图从根上重画|
| B · 程序化派生 | 保持 winter 像素几何不动，只调 HSV | 121 组参数全不达标；「与 autumn 的差」在整个参数域上**最小值19.29**，从没接近上限 16 | autumn↔winter 的 22.40 主要来自**元素分布**（岩石/植被/岸线）而非色调 ⇒ 改色在**原理上**就靠不近 |

⇒ 两条路线的失败指向同一结论：**这个缺口只能靠真有中间态的素材填**。
当前保留 22.40，8s 交叉淡入已验证可接受。
