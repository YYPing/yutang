# 项目真实情况（2026-10-08 盘点）

⚠️ **这份文档的用途**：README 面向「使用者」，发布文档面向「这一版改了什么」。
而**这一份记录「实际验证到什么程度」** —— 因为本项目的 README 里有过时描述，
而发布文档只在版本推进时更新，中间隔着的**未验证区**没人写，于是被当成了「已支持」。

盘点方式：所有结论都来自实跑或**直接读源码**，读不出来的明确标「未验证」。

## 一、平台支持：README 有过时描述

README 原写「Windows/Linux 的原生桌面层尚未实现」。**这句话不准确**，真实情况是三层：

| 层 | 状态 | 依据 |
|---|---|---|
| **网页预览**（`pnpm dev`，端口 5188） | ✅ macOS / Windows / Linux 都可用 | 两个主题都是 Canvas/WebGL，无平台专有 API |
| **桌面应用**（`pnpm desktop`，Electron 37） | ⚠️ **macOS 已验证；Windows 能跑但未做平台专项；Linux 未验证** | 源码里**没有任何 `process.platform === 'win32'` 分支**（只有 `LAUNCH_AT_LOGIN_OK = ['darwin','win32']` 与一处菜单判定），意味着 Windows 走的是与 macOS 相同的代码路径 |
| **壁纸模式 / 鼠标穿透** | ⚠️ 同上（`setIgnoreMouseEvents` 在 167/193 行，无平台分支） | 同上 |

### 一个必须点名的陷阱：`test:windows` 这个名字是错的

`package.json` 里有 `"test:windows": "node electron/window-habitat-1.10-smoke.cjs"`，
**但它内部硬编码了 macOS 的可执行文件路径**：

```js
executablePath: path.join(root, 'node_modules/electron/dist/Electron.app/Contents/MacOS/Electron')
```

⇒ 在 Windows 上这条命令**跑不起来**，它的名字会让人误以为「Windows 已覆盖」。
（同类的还有 `work/1.10` 这个相对路径假设。）

⇒ **判据的名字也是文档的一部分**。名字撒谎比没有判据更坏 —— 它让人以为测过了。

### ⚠️ 但「量具多」不等于「覆盖全」，有三条已知缺口

1. **`npm run test:eco` ⑤ 长期红**（2026-10-08 实跑确认仍红，非陈旧记录）：
   需求 §17 写「50–60 代」，实测稳定在 **26–32 代**（26 条中 7 条成熟，~27%）。
   量具自己给出了 4 个解法，但**都需要需求方拍板**，本项目不自行选择：
   | | 解法 | 代价 |
   |---|---|---|
   | A | 接受实测值，把 §17 改注为「理想上限，实测 26–32」 | 改需求 |
   | B | 降 `nutritionPerCm`（1.2→0.3） | **会削弱 US-2 的投喂收益梯度** |
   | C | 放宽 F-7.4.1，让自然饵料补少量 nutrition | 当前明确不补 |
   | D | 降鱼苗胁迫倍率（×3→×1） | 量具注明**实测无效**，不推荐 |

   ★ 已排除的两个方向（量具实测过，放宽软上限 30→60、提高繁殖触发率 0.5→3.0
   **均无效**，世代仍在 26–32）⇒ 这不是调参能解决的，是需求与实现的模型不匹配。
2. **`test:windows` 不可用**（见上）。
3. ~~焦散 UV 流动未做~~ —— **盘点时才发现这条是错的**：焦散光网（`causticNet()`）
   已实现，且**含 UV 流动**（`drift=vec2(t*.13,-t*.09)` + 两层域扭曲）。
   实跑 `npm run check:caustic` = **5/5 通过**（占空比 3.2%、随时间流动、
   内部形变非平移、峰均比 49.8×、cells 是真控制）。
   原记录来自 shader 里一句 `No displacement or oscillating lighting`，
   **那句注释在实现焦散时就被删了**，而「未做」清单没跟着删。
   ⚠️ 这是本次盘点最有价值的一条发现：
   **「已知未做」清单会过时，而过时的那一条最容易被下一轮当真**
   —— 我自己今天就差点照它去「实现」一个已经存在的东西。

### 哪些量具必须先起 dev server

浏览器类量具统一认 `TERM_URL`（默认 `http://127.0.0.1:5188/`）。
**写死 `127.0.0.1` 的量具在 Vite 只监听 `[::1]` 时会全部 `ERR_CONNECTION_REFUSED`**，
表现为「同一台 server 上量具时好时坏」—— 极易误判成画面回归。

纯 Node 类（不需要浏览器）：`npm test`·`check:lotus:pheno`·`check:terms`·`probe:desktop`。
