## 一、起点：数据已经算好了，只差接线

**关键发现**：`getSolarTerm(date)` 已经用黄经每15° 一档算出了精确到分钟的节气，
`env.solarTerm` 也已经传进渲染 options（`App.jsx` L52）。但它现在**只出现在 HUD 文字里**
（`· 立春`），对画面零影响。

所以本规划不是「从零做节气系统」，而是**把已有数据接到 5 类渲染通道上**。

### 现状的三个缺口

| 缺口 | 现状 | 应为 |
|---|---|---|
| **季节粒度太粗** | `season` 只有 4 值（春夏秋冬） | 24 节气连续谱 |
| **昼夜只有开关** | `night` 是布尔，白天/黑夜两态 | 6 段连续插值（黎明/清晨/正午/黄昏/入夜/深夜） |
| **节气空转** | 只显示文字 | 驱动物候、色温、植被、动物 |

## 二、三维正交驱动

三轴**互相独立**采样，任一变化只影响对应通道，互不干扰：

```
昼夜（6 段，本机时间）──────┼──▶ 五类渲染通道
天气（6 值，实时 API）──────┘
```

## 四、昼夜六段

| 段 | 时间（示意） | 环境光 | 色温倾向 | 焦散 | 特征 |
|---|---|---|---|---|---|
| **黎明** | 05:00–07:00 | .32 | 暖橙 [.1,.86,.72] | 0.30 | 水面雾气最重、锦鲤最活跃 |
| **清晨** | 07:00–09:00 | .35 | 暖白 | 0.75 | 露珠、蝴蝶出没 |
| **正午** | 09:00–15:00 | .36 | 中性[1,.98,.94] | 1.00 | 光网最密、光柱最强 |
| **黄昏** | 15:00–17:00 | .31 | 暖金 [1,.78,.58] | 0.25 | 最长光影、水面反光 |
| **入夜** | 17:00–19:00 | .29 | 冷蓝 [.7,.8,1] | 0.10 | 归巢、涟漪增多 |
| **深夜** | 19:00–05:00 | .28 | 冷蓝 [.62,.72,1] | 0.06 | **萤火虫**（小暑前后最强）、星空倒影 |

### 昼夜连续插值（避免跳变）

**不要用布尔跳变。** 现有 `night` 布尔在切换瞬间会「啪」一下变暗。
改为按时间连续求值，黎明/黄昏各留**90 分钟过渡带**：

```js
// 建议：日相位 → 三通道权重
const phase = ((hour + minute/60) - 6) / 24 * 2 * Math.PI;
const dayFactor= 0.5 + 0.5 * Math.cos(phase);   // 1=正午 0=午夜
```

夜间**不是纯黑**——保留 0.28 环境光（需求 §10.5 硬值），靠**色温偏移**而非压暗来表达夜。

### 各通道的节气/昼夜映射

- **光影**：焦散强度 = `day.caustic × CAUSTIC.weather × TERM_PROFILE.warmth`；夜间加月光冷偏移
- **水色**：浅区黄绿→深区青蓝（参考图口径），冬季转冷灰蓝并加冰层高光
- **植被**：荷叶覆盖率 = `TERM_PROFILE.leaf`；落叶密度 = `TERM_PROFILE.litter`
- **动物**：**只在"物候允许且昼夜合适"时出现**——如萤火虫仅夜间 + 小暑前后；蝶仅白天 + 春季
- **粒子**：节气决定粒型（春雨/夏雷/秋叶/冬雪），昼夜决定密度
- **生态**：正午活跃度最高，夜间降低；**黎明黄昏为投喂最佳窗口**（呼应「清晨/黄昏」的设计意图）

## 八、已定决策（2026-10-03 用户拍板）

### ① 节气切换用**渐变**
当前节气 → 目标节气在 **2–3 天内插值**。避免每天中午「啪」地变一次。
实现：`solarTerm` 返回当前档位与**黄经连续角度**（已有算法，改动极小），
渲染层用 `mix(profileOf(prevTerm), profileOf(nextTerm), t)`，t 由距交节的度数推进。

### ② 增加「时令模式」开关
三种取值，用户可切：
| 模式 | 行为 |
|---|---|
| `follow` **跟随真实节气**（默认） | 用`getSolarTerm()` 实际结果 |
| `manual` 手动指定 | 设置面板列出 24 节气，选中即预览 |
| `cycle` 演示轮转 | 每 3 秒推进一个节气，用于展示与截图 |

手动/演示模式**必须打标记**并写进存档，否则重启后跳回真实节气会让用户以为出bug。

### ③ 冬季冰封**留一处活水泉眼**
全池冰封，但在固定位置（建议池心偏右，坐标约 0.68/0.62）留一处**不结冰的活水**：
- 冰层用形状挖一个不规则孔洞，孔内水色回到夏态（不降亮）
- 泉眼周围有**蒸汽**（晨昏更明显）与**气泡**（冬季一直在冒）
- 鱼会**向泉眼聚集**——给冬季场景一个视觉焦点，也避免「鱼被困死」的观感
- 泉眼是**季节性**的：仅冬季 + 霜降后出现，其他季节隐去

### ④「节气一天」效果图
已产出交互式效果图：单节气下 0:00–24:00 的连续光影变化
（色温、环境光、焦散、光柱角度、鱼活跃度、物候六项同步演化）。

| 文件 | 作用 |

| `tools/check-almanac-ui.cjs` | 真浏览器 26 项验收（挂 `npm run check:almanac`） |

### 数据流
```
真实黄经 solarLongitude()          ← environment.js新导出
   ↓ almanacFromLongitude()→ { term, index, t∈[0,1), season }
   ↓ blendTerm(term, t)             ← 六维档案插值（离散维过半程整块切）
options.almanacProfile             ← App.jsx options（构造段 + 依赖数组都有）
   ↓ PondEngine.updateOptions()
   ├→ env.solarTerm  → HUD 文字 + 深冬判据
   └→ env.season     → 背景贴图 / CAUSTIC.season / SEASON_LIGHT
```

### 三个必须知道的实现决定

1. **`follow` 走黄经，不走 `getSolarTerm()`**。
   后者每 15° 跳一档，视觉上是每半个月"啪"变一次；黄经连续，`t` 天然就是过渡进度。

2. **非follow 时季节由节气接管**（`useEnvironment` 的 return 里）。
   否则「翻到大雪还是满池荷花」——开关等于白设。
   代价：季节滑杆在这两种模式下失效，所以 `SeasonPanel` 里四张季节卡会变暗并写明原因。

3. **`cycle` 的档位与过渡都由 `cycleOffset(墙上时钟)` 推导**，不读 state计数器。
   ⚠️ 渲染不重算 ⇒ 渲染里读 `Date.now()` 只会拿到上次的旧值，
   过渡量会冻结成随机数（第一版踩过）。现在靠一条**仅 cycle 模式挂载**的 600ms interval 驱动重渲染。

4. **每档前 55% 稳停、后 45% 渐变**（`CYCLE_HOLD` / `cycleBlend`）。
   全程渐变的话画面永远在变，看不出"现在是哪一档"。

## 十、第 2 步实施记录（2026-10-04，提交 `09f166b`）

### 起因
用户反馈「**每个节气之间都一样**」。这不是观感问题，是三层静默失效叠加：

| 层 | 现状 | 后果 |
|---|---|---|
| 背景贴图 | 只有 4 张（`spring/autumn/winter/pond.png`），按 `season` 索引 | 同季 6 节气**共用一张图** |
| 焦散 | `CAUSTIC.season` 只有 4 个值 | 一季一档 |
| 物候档案 | 六维只被读 1 维（`ice` → 雪片 18→28） | 其余 5 维零消费 |

⇒ 24 个节气实际塌成 4 张画面。

### 做法
新增 `src/engine/term-visual.js` 作翻译层（档案 → 渲染参数），三条铁律：
**只加不减**（不替换贴图/光照场/锦鲤画法，避免打破已钉死的基线）·
**同季节内部必须有差异**（背景图季节级共享，组内差异只能来自水色与焦散）·
**连续优先于精确**（宁可 .98 不写 1.0，留插值余量）。

接入点：`pond.js` 荷叶门控改档案驱动 + `drawLotus` 按数量生成 ·
`landscape.js` 加 `uTermTint` 水色通道 · `drawIce()` 全面接档案 + 新增 `drawIceHole()`（冬季活水泉眼）。

### 三处「饱和」病（同一个病的三个马甲）

| 位置 | 症状 | 正解 |
|---|---|---|
| 档案撞上界 | 夏至 `warmth/leaf/lotus` 全 = 1 | 峰值改 .99/.96（`Math.round(leaf*MAX)` 在 leaf→1 时必然饱和，**靠调 MAX 解决不了**） |
| uniform 溢出 | `0.72+tintR*0.56` 让 R/G 在芒种后 >1 被 clamp | 按**实际取值域反推**基址（0.70/0.78/0.66） |
| `iceHole` 只由 `ice` 推 | 而 `ice` 在冬四档全 = 1 | 半径改由 `deepWinter` 序号驱动（闸门仍用 `ice`：薄冰上不该有洞） |

### 实测
- 冬六档像素差 **0.00%（逐像素相同）→ 0.61%~6.37%**
- 相邻档中位差 1.63%，同季节组内最小 0.29%（惊蛰→春分），噪声底 **0.000%**
- 荷叶画面占地与档案 `leafCount` 的 Spearman **ρ = 0.996**（24 档）

### 量具（两支，缺一不可）
- `npm run check:terms` → `tools/probe-terms.mjs`：参数级，39 项
- `node tools/shot-terms-ui.cjs`：像素级，16 项（需 dev server 在 5188）
