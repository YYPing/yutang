## 核查方法（两把尺子，互为交叉验证）

**尺子一 · 需求编号逐条对照** —— 按 §2 用户故事（US-1…US-13）、§4/§5 功能编号（F-x.y）、
§18 里程碑逐条比对实现状态。

**尺子二 · 常量引用率体检**（`pnpm run check:dead`）——
`src/engine/eco/constants.js` 是照 §17「核心数值参数总表」**逐条抄下来**的，每条都标了来源条款。
于是：**一个常量如果从来没有任何模块读过它，它对应的那条需求就大概率没落地。**
实测 94 个键里 25 个未被读。

这个方法的好处是**不会漏** —— 漏掉的功能几乎总是"常量抄了、代码没写"这种形态，
而不是"连常量都没定义"。

## 三、口径偏离（不是"缺"，是"文档与实现两套说法"，需拍板）

这四项**不是遗漏，是本体的既成事实与 v4 文档不一致**。改与不改都要明确，否则以后每次对需求都会再吵一遍。

| 事项 | v4 需求 | 本体现状 | 说明 |
|---|---|---|---|
| 壳层 | Tauri 2 + `tauri-plugin-wallpaper`（D1） | **Electron 37** + 自研 `pond-window.node` | 本体已实现 WorkerW 嵌入 / 鼠标穿透 / 托盘 / 无边框，**实测通过**。切 Tauri 是重写级工程 |
| 渲染器 | PixiJS / WebGL 为主（D15） | **Canvas 2D** | 本体 1080p 满帧运行且测试齐全；PixiJS 的收益（多层混合 / LUT / 软粒子）在光池光柱等氛围功能上才明显 |
| 运动模型 | §12 三条铁律 + 体波参数 | 本体自有模型 | `MOTION` 17 键**14 个未读**。本体运动看起来是对的，但 **§12 的量化验收指标（转弯半径/直游占比/铺展指数）没有任何工具在跑** |
| 主题 | zen / ink / night 三套 | koi / coast 两套 | 「赶海」是本体自带的第二主题，v4 文档完全没提 |

## 四、建议推进顺序（按"解锁能力"排序，不按工作量）

1. ~~**演化倍速**~~ ✅ —— 成本最低、解锁最多。没有它，下面每一条都只能靠离线推演验收，人工看不到效果。
2. ~~**生态快照 + 离线补算 + 归来摘要**~~ ✅ —— 补上 US-7，让"它是活的"这个核心命题真正成立。
3. ~~**投喂感应圈**~~ ✅ —— US-1 是 P0，且是实现度最低的一条 P0。
4. **繁殖可视化 + 面板数据 + 个体档案** —— 让已经很完整的生态内核**被看见**（数据都有了，主要缺渲染与展示）。
5. 再往后才是氛围向（池灯 / 光柱 / 冲刺 / 节气物候）与桌面层（遮挡暂停 / 多屏）。

> 一句话总结：**生态内核已经做完了，P0 三条也已收口，缺的是"让它看得见"。**
> 当前最大的洞是 P1 的「可见性」组（#5–#10：繁殖全过程、老鱼表现、鱼苗半透明、幼鱼花纹、低饱食惩罚、APPETITE 基因）——
> 数据与算法大多已在 `src/engine/eco/` 里算好了，缺的是渲染与展示。
